# Open-source harness research — findings and adoption plan

Mined 8 cloned repos under `Agent Harness/`: OpenHands, SWE-agent, aider, cline, goose, hermes-agent-self-evolution, mini-swe-agent, opencode. All code cited below was read directly (file:line), not inferred from README claims. Full per-repo reports live in the background-task transcripts of this session; this doc is the synthesis and the action plan.

**Dead end:** the `OpenHands` checkout is only the "Agent Canvas" web control-panel frontend (TypeScript, talks to an external agent-server process over HTTP). No agent-loop code exists in this checkout — 3 Python files total, all CI scripts. If OpenHands' actual controller/condenser code is wanted, a different repo needs to be cloned (the agent-server/SDK package, not this UI).

**Thin repo:** `hermes-agent-self-evolution` is mostly a plan document; only ~1,850 lines of real code, all offline (GEPA-based prompt-text evolution via PR, never touches a live agent loop). One reusable idea: secret-scrubbing regex before persisting any transcript to a memory/telemetry store.

## Codexa's known problems, mapped to what other harnesses do

### 1. Stall blindness — `rounds_spent` never increments during a stalled round

This is Codexa's most specific, most confirmed-live bug. Findings across repos:

- **goose** (`crates/goose-agent/src/operation.rs:44-56`) computes turn count as a **pure function over persisted messages**, recomputed every check — never an imperatively incremented int. Structurally cannot desync from reality. **This is the fix.** Codexa's `controller.record_round()` should be replaced (or backed) by deriving `rounds_spent`/`rounds_without_progress` from the on-disk task-event log, not from a counter that a stalled-round code path can skip incrementing.
- **goose** also has an independent, orthogonal stall guard: `crates/goose/src/tool_monitor.rs` (`RepetitionInspector`) hashes `(tool_name, args)` and denies after N consecutive identical calls — fires regardless of whether the round-counter bookkeeping is even correct. Cheap to bolt onto `backend/agents/tools.py`'s dispatch path as a second, independent line of defense.
- **cline** has the most complete version of this: `LoopDetectionTracker` (`loop-detection.ts:125-162`) hashes `(toolName, sortKeys(JSON(input)))` — key-order-independent — with a soft threshold (3, inject a "change approach" message into the live conversation) and hard threshold (5, force-stop). Separately, `MistakeTracker` (`mistake-tracker.ts:80-159`) generalizes "stall" beyond tool-repeat to also count API errors, invalid tool calls, and failed tool executions — reset to 0 on *any* turn with a successful tool call. At the limit, a host callback decides `continue` (inject corrective guidance, reset counter) vs `stop` — the host, not the model, has final say.
- **SWE-agent** (`agents.py:498,969,989`) has a dedicated `_n_consecutive_timeouts` counter, separate from the step counter, reset only on success, threshold-raise (`tools.py:150`, default 3). Same shape, narrower scope (just timeouts).
- **Both SWE-agent and mini-swe-agent confirm this is genuinely unsolved territory in the wild**: neither has cross-round identical-action detection in its main loop (mini has zero stall detection at all beyond flat step/cost/time limits; SWE-agent's duplicate-filtering only exists across *parallel* samples in an optional mode, not sequential rounds). Nobody but goose/cline actually solved this.

**Recommendation:** implement goose's derived-counter fix as the structural correction, then layer cline's two-tier (tool-signature loop detector + generalized mistake tracker with host-decided continue/stop) on top. This directly targets the exact bug diagnosed live this session (job `aa56230d`: 23 stalled rounds, `rounds_spent: 0`).

### 2. Hang diagnosis — 90s watchdog fires but no visibility into what was stuck

- **goose**: `debug!("WAITING_LLM_STREAM_START")` / `"...END"` and `WAITING_TOOL_START: {name}` / `"...END"` bracket every hang-capable await (`reply_parts.rs:387,398`; `agent.rs:1178,1193`). Trivial, immediately actionable — last log line names exactly what's stuck. **Do this first, it's a 20-line change.**
- **goose**: `last_activity: AtomicU64` updated on every subagent message, idle-time computed on demand (`now - last_activity`) and exposed alongside turn count in a status-peek call (`summon.rs:2085-2094, 1108-1141`) — no dedicated watchdog thread needed, just a timestamp + a poll endpoint. Add `last_activity_ts` to the job/task record, update on every stream chunk/tool-result, surface in whatever status endpoint `jobs.py` serves.
- **goose**: bounded synchronous waits never block indefinitely — `tokio::select!` against a hard ceiling (5 min), and the timeout error names the exact recovery action ("poll again, or cancel:true to stop") rather than a bare exception (`summon.rs:1204-1219`). Cancel itself has a grace period then force-abort (`summon.rs:1155-1165`).
- **SWE-agent**: two-tier timeout — per-command (30s) vs cumulative session wall-clock (1800s), distinctly-named exceptions so logs disambiguate "one round is slow" from "the whole job has run too long" (`tools.py:139,145`; `agents.py:1017-1018`). On a command timeout it actively tries to interrupt the stuck session and logs if the interrupt itself fails (`agents.py:967-978`) — closest thing found anywhere to real hang diagnosis rather than passive waiting.
- **opencode**: on panic, dumps a timestamped file with the panic value + full stack trace, still runs cleanup, posts a persistent UI-visible log entry (`logger.go:64-93`, `RecoverPanic`, wired at every goroutine boundary).

**Recommendation:** (a) bracket logging around the LLM-stream await and each tool-dispatch call in `jobs.py`/`controller.py`/`tools.py` — cheapest, highest-value item in this whole report; (b) add `last_activity_ts` + idle-seconds to job status; (c) split the 90s watchdog into per-round vs cumulative-session ceilings with distinct exception names; (d) on watchdog fire, dump a structured state file (round, last tool call+args, elapsed since last chunk, active task stacks) rather than just raising.

### 3. Context staleness — design guidance ages out of context before authoring rounds need it

This is the deepest and most contested topic across repos — five genuinely different architectures were found:

- **opencode** confirms the failure mode structurally, doesn't solve it: compaction is reactive (checked after each response, triggers at 95% of context window), collapses *everything* before the trigger point into one prose summary from a separate summarizer model, replayed as a fake `User` turn. All structured tool-call/diff content is lost — this is Codexa's exact bug, reproduced by design in another harness.
- **goose** has the strongest fix: compaction is a **visibility flag**, never a deletion — messages get tagged `agent_invisible` while staying `user_visible` for the transcript UI (`context_mgmt/mod.rs:143-158`); all prompt-building filters on `is_agent_visible()`. Nothing is ever unrecoverable, "un-aging" a result is a flag flip. On top of that, `protect_last_n` **hard-excludes the most recent N tool calls from summarization eligibility at all**, sized proportionally to context-window fraction (`mod.rs:378-399`) — structurally cannot touch current-task tool results. Per-pair background summarization (one aged tool result → one sentence, via a cheap separate model call) is incremental, not a whole-history recompaction (`mod.rs:224-238,266-336`).
- **SWE-agent**'s `history_processors.py` is the most surgical: full history is *kept forever*, a stateless processor chain re-derives what's shown to the model **fresh on every query** — not a one-way destructive compaction baked into stored state. Concretely: `LastNObservations` elides old tool outputs to a line-count placeholder but has an explicit **tag-based pin override** (`always_keep_output_for_tags={"keep_output"}`) that beats the N-window recency rule; `TagToolCallObservations` auto-tags outputs by *originating tool name*, so "commit_direction and get_design_guidance outputs are always load-bearing" can be declared once in config rather than hand-tagged per call. `ClosedWindowHistoryProcessor` collapses stale *duplicate views of the same resource* (re-fetching the same file) rather than blind recency — content-identity-aware, stronger than age-based truncation.
- **cline** takes a third approach: no arbitrary per-message pinning exists at all. Instead, the important *fact* (e.g. which files were touched) is extracted into a small structured dict at the point it's produced, force-injected into every compacted summary via `ensureFilesSection` (`compaction-shared.ts:412-449,647-655`), stored as plan-adjacent state rather than raw conversation history. Compaction outputs are frozen once produced (`metadata.compaction="preserved"`) so repeated compaction only processes the new tail, never re-degrades already-summarized content.
- **aider** solves a related-but-different problem (context *selection*, not staleness): `RepoMap` ranks candidate context by PageRank over a reference graph, personalized toward what's currently open/mentioned, binary-searched against actual token cost, cached and only recomputed when materially stale (`repomap.py:365-574,666-706,592-627`).

**Recommendation — pick one, they don't compose cleanly:**
- **Cheapest, highest-leverage fix matching Codexa's exact bug**: adopt SWE-agent's tag-based pin. Give `commit_direction`/`get_design_guidance` tool results a `keep_output` tag at the point they're produced in `backend/agents/tools.py`, and have whatever assembles round context in `plan.py`/`controller.py` treat tagged results as exempt from the N-round staleness rule, full stop. This is a small, surgical change and directly answers the diagnosed root cause (design guidance 5+ rounds stale by authoring time).
- **If a deeper rework is wanted later**: goose's visibility-flag model (never delete, only hide) is the most architecturally sound long-term direction — it also makes post-hoc debugging of "why did the model do X" possible forever, which Codexa doesn't have today.
- **Do not copy** opencode's whole-history-to-one-prose-blob approach — it's confirmed to be the failure mode itself, not a fix.

### 4. Bounded retry / self-healing

- **mini-swe-agent** has the cleanest reference: limits checked once as a precondition at the top of the step, single incrementing counter, consistent "0 = unlimited" sentinel across step/cost/wall-time/format-error limits (`default.py:130-152,104`). Format-error counter is **consecutive, resets on any clean step** — not cumulative — avoiding premature kill of a long, mostly-healthy run with one bad early patch.
- **SWE-agent**: retry-worthy vs fatal-immediately is an explicit exception-type allowlist (`retry_if_not_exception_type((ContextWindowExceededError, CostLimitExceededError, AuthenticationError, ...))`, `models.py:813-830`) rather than one generic retry-everything loop.
- **goose**: transient-vs-permanent classification includes hardcoded permanent-failure message substrings (retrying a byte-identical payload that hit an immutable-thinking-block 400 can never succeed, so it's special-cased out of the retry set); auth-refresh is a separate one-shot retry lane outside the main retry budget; retry only fires **before the first stream chunk has been yielded** — once real content has started flowing to the user, a later error is surfaced directly rather than silently retried (which would risk duplicating/corrupting delivered output) (`retry.rs`, `reply_parts.rs:410-462`).
- **cline**'s `retry-empty-response.ts` is the most sophisticated: buffers each attempt client-side until the first real output part arrives, only then "accepts" and flushes it live — a discarded (empty/dead) attempt never leaks partial garbage into the logical stream even across N retried HTTP calls. Separately classifies empty-response retries (soft finish reasons only, tool-call-only turns never retried) from transient-network retries (explicit socket-error allowlist, only if nothing emitted yet). Crucially: **token usage from discarded attempts is folded into the final cost ledger, never silently dropped** (`withAggregatedUsage`).
- **aider**'s single shared reflection counter across all failure classes (malformed edit, lint fail, test fail) is flagged by its own miner as a design weakness — explicitly *not* recommended to copy; use per-failure-class budgets instead (matches Codexa's existing per-cause classification design, which is already better here).

**Recommendation:** Codexa's TokenRouter/GLM call site should adopt (a) exception-type-based retry-worthy/fatal-immediately classification, (b) buffer-until-first-token so a retried attempt never corrupts a partially-delivered stream, (c) fold discarded-attempt token usage into cost tracking rather than losing it. Keep the existing per-cause classification (`cap_before_commit`/`cap_after_commit`/`wall_clock`/`needs_structure`) — it's already more granular than most of what was found.

### 5. Plan/task decomposition and design-commitment durability

- **cline**'s `agenda_tasks`/`agenda_task_runs` schema (`task-schema.ts:4-97`) is close to a direct blueprint for `plan.py`: task rows with a status enum, **optimistic concurrency via revision integers**, a separate run-attempt table with lease-based claiming (`claim_token`/`claim_until_at`) and a **DB-enforced partial unique index** guaranteeing only one active run per task (no app-level locking needed). Crash reconciliation on restart sweeps any run left `starting`/`running` back to `pending_approval` or `failed` with an explicit restart message — never silently orphaned. A rate/concurrency governor caps starts-per-hour and max chain-depth (walking origin-task ancestry) to bound agent-spawns-agent recursion, directly relevant to Codexa's `feat/task-driven-execution` branch if sub-plans are ever allowed to spawn sub-plans.
- **SWE-agent has zero persistent plan machinery** and still hits its benchmark numbers via ACI + bounded retry + history management alone — a genuine negative data point. Whether Codexa's `ExecutionPlan` state machine is worth its complexity is a real open architectural question this doesn't resolve either way, just flags it as a real divergence from a working alternative.
- **goose**'s `Operation` trait — each policy concern (max-turns, retry/goal-nudge, exit-on-error, compaction, tool-approval) is an independently testable unit composed into an ordered pipeline over persisted state, rather than branches accumulated in one function (`goose-agent/src/operation.rs:74-131`; pipeline list in `state_machine/mod.rs:9-29`). Notably, goose's own `controller.py`-equivalent docstring **self-diagnoses the same "grew by accretion" problem** Codexa's `controller.py` docstring already admits to. This is the architectural fix for that admitted problem, not just an idea — worth prioritizing if `controller.py` continues to accrete special cases.
- **goose**'s turn-budget self-disclosure to the model (`<turn-budget>{taken}/{max} used</turn-budget>`, only surfaced past halfway, paired with explicit "become more direct as budget gets low" system-prompt instructions, `moim.rs:66-118`) lets the model self-regulate rather than the harness only reacting after a forced cut. Directly portable onto Codexa's existing `_DIRECTIVE_MARKS` injection channel — add a standing budget-status line.

**Recommendation:** goose's `Operation`-pattern refactor is worth doing regardless of anything else — it's a direct answer to a problem `controller.py` already admits having. The turn-budget self-disclosure line is a 1-day add to the existing directive channel. cline's task-schema is worth adopting piecemeal (revision-based concurrency + crash-reconciliation sweep) rather than wholesale, since Codexa's persistence layer specifics weren't compared here.

### 6. File edit safety / lint-on-write

Codexa's existing lint-on-write-with-revert (per-script-block diffing, safe full-content revert) is already **stricter than every harness examined** — none of aider, opencode, or cline auto-revert on lint failure; they all leave the bad edit on disk and feed diagnostics back for the model to self-correct next round. Two concrete improvements worth taking anyway:

- **SWE-agent**'s `tools/windowed_edit_linting/bin/edit` diffs pre-edit vs post-edit lint output and only surfaces **newly introduced** errors — pre-existing file lint debt never blocks an edit. It also puts a specific anti-stall sentence directly in the tool's own error message: *"DO NOT re-run the same failed edit command. Running it again will lead to the same error."* — a prompt-level device baked into the tool response itself, complementary to (not a replacement for) controller-level stall detection. Cheap to add verbatim to Codexa's lint-failure message.
- **aider**'s fuzzy-edit matching is **deliberately dead code** (`editblock_coder.py:183`, unconditional early return before the fallback) — a real design decision to prefer exact/structural matching over similarity-based matching, specifically to avoid silently applying a "close enough" edit to the wrong location. Worth confirming Codexa's own `edit_file` never does fuzzy/similarity matching either.
- **opencode**'s edit tool has a stale-read optimistic lock: refuses to edit unless the file was read this session and refuses if its mtime changed since that read (`edit.go:259-268`) — cheap concurrent-modification guard worth checking Codexa has.

### 7. Repository health / checkpointing

- **cline**'s checkpoint mechanism (`checkpoint-hooks.ts`, `checkpoint-restore.ts`) is the strongest match for Codexa's repo-clone-health work: instead of a shadow clone, it snapshots via `git stash create` (never touches working tree/index/HEAD) into **private refs** in the user's own repo (`refs/cline/checkpoints/...`, invisible to `git stash list` but GC-reachable), with a graceful degradation ladder (full stash → HEAD-only commit → skip, every outcome telemetered, never silently swallowed). Restore itself is **transactional**: before the destructive `git reset --hard && git clean -fd`, it takes a safety snapshot, rehomes it to a private ref, and exposes explicit `commit()`/`rollback()` — a bad restore attempt is itself recoverable (`checkpoint-restore.ts:50-154`). This is directly transplantable to `backend/repository/api.py` as a much lighter-weight alternative to the temp-clone-then-atomic-swap approach already built this session, usable for *in-place* safety snapshots before Codexa's own agent writes to a loaded repo (not just at load time).
- **aider**'s git-safety patterns are also directly relevant: a single aggregated exception tuple (`ANY_GIT_ERROR`) used consistently at every git call site for uniform degrade-not-crash handling; auto-commits pre-existing dirty state before the agent touches a file, isolating agent diffs into their own atomic commit so `/undo` never has to disentangle them; `/undo` itself has 5 layered preconditions (own-commit-only, not pushed, not a merge, file still exists in parent, no new dirty changes since) before reverting anything.

**Recommendation:** cline's private-ref stash-snapshot pattern is worth adding to `backend/repository/api.py` as a pre-write safety net (snapshot before Codexa's own agent starts editing a loaded repo), independent of the load-time clone-health work already done this session. aider's dirty-state-isolation-before-edit pattern is a good complementary addition if Codexa ever writes into a git-tracked repo the user is actively working in.

### 8. Standout ideas outside the numbered problem list

- **goose**: oversized tool-result spill-to-file (200k char threshold) — result replaced with a path pointer + byte count, model reads it back via existing file tools instead of the full blob blowing every subsequent round's context (`large_response_handler.rs`). Directly applicable to `backend/agents/tools.py` for any large repo-analysis or graph-dump tool output.
- **aider**: prompt-cache breakpoints placed at content-stability transitions (system → examples → repo-map → history → chat-files → current-turn), not on every message; plus a bounded background keepalive-ping thread (hard ping-count cap) to survive Anthropic's 5-minute cache expiry during idle gaps. Maps almost directly onto `backend/agents/round_telemetry.py`'s in-progress cost work.
- **SWE-agent**: adaptive-compute self-consistency — cheap read-only rounds get 1 sample, risky state-mutating rounds get N parallel samples with duplicate-filtering, survivors shown back to the model as alternatives to pick/synthesize from (`action_sampler.py`). Portable as an optional multi-sample pass gated specifically on "this round is about to write."
- **SWE-agent**: flat, stable exit-status vocabulary (`exit_forfeit`, `exit_cost`, `exit_format`, `exit_context`, etc.) embedded directly in trajectory/telemetry data, and every fatal path tries to salvage the last known-good diff before giving up rather than returning nothing.
- **cline**: sub-agent delegation as a single self-contained tool (`spawn_agent`) with isolated conversation, lineage tracking, separate token/iteration accounting, and lifecycle hooks where observer-callback errors are swallowed so they can never break task execution — a clean minimal pattern if Codexa ever wants sub-agent delegation.
- **opencode**: append-only persistence + a "context floor" pointer reconstructed at read-time — full history retained in SQLite forever, compaction is a view-time concern, never a deletion. Same underlying idea as goose's visibility flag, different implementation layer (DB row vs in-memory tag).

## Suggested priority order (highest value ÷ effort first)

1. **Bracket logging around LLM-stream and tool-dispatch awaits** (goose pattern) — ~20 lines, immediately answers "what was stuck" the next time the watchdog fires.
2. **Tag-based pin for `commit_direction`/`get_design_guidance` outputs** (SWE-agent pattern) — small, surgical, directly fixes the diagnosed design-guidance-staleness bug.
3. **Derived round/stall counter + independent tool-signature repeat detector** (goose + cline pattern) — fixes the exact `rounds_spent: 0`-during-stall bug diagnosed live this session on job `aa56230d`.
4. **`last_activity_ts` + idle-seconds on job status, split watchdog into per-round vs cumulative-session ceilings** (goose + SWE-agent pattern) — cheap, improves both diagnosis and operator visibility.
5. **cline's private-ref stash-snapshot as a pre-write safety net in `backend/repository/api.py`** — complements the clone-health work already shipped this session with an in-place undo capability.

Items 6+ (Operation-pattern controller refactor, task-schema persistence rework, retry-buffer-until-first-token, oversized-result spill-to-file, adaptive self-consistency sampling) are larger and worth scoping individually once the above land.
