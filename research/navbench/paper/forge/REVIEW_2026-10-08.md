## 1. Understanding the paper

| Item | Content (page/section) |
|---|---|
| **Research questions** | Q1: how does the choice of baseline change token ratios? Q2: how does sampling targets independently of the graph change coverage and rankings? Q3: under a common output form, with labels no tool produced, which tools reach useful token–quality operating points? (p.1, §I) |
| **Contributions** | (1) A benchmark harness with three independent label layers, validity gates and output-form control. (2) For the same graph outputs, the ratio spans more than two orders of magnitude depending on baseline and form. (3) Graph-conditioned sampling overstates coverage and recall. (4) Pattern-level correctness profiles and runtime-observed recall (p.1) |
| **Method** | **T1:** direct call sites of a target. **T2:** definition lookup (§II). **Layer A:** generated Python/TypeScript fixtures whose manifests are checked by execution (Python) or compilation (TypeScript); 16+16 held-out fixtures, 224 targets, 160 with explicit call sites. **Layer B:** 9 Python + 8 TS/JS libraries, with targets enumerated by `ast` and the TypeScript compiler API; S-ind has 585 targets and S-cond 331. **Layer C:** calls observed under `sys.monitoring` while each Python test suite runs |
| **Arms** | rg -w (with 0 and 3 lines of context); pyright 1.1.414; TypeScript 5.9.3 language service; G1 `find_references`; G1 `lookup+deps`; codebase-memory (current and v0.5.7) |
| **Metrics** | Caller-, site- and file-level recall and precision; complete answer = caller recall of 1; cl100k tokens in native, location and source-enriched forms; repository-macro means with hierarchical-bootstrap CIs; a frozen primary contrast with a 1.5× margin |
| **Main results** | Table I (Q1 ratios); Table II (Q2 S-cond → S-ind); Table III and Fig. 2 (Q3 fixtures); §III-D (Layer C) |
| **Stated limitations** | Payload ≠ agent cost; fixtures are cleaner than real code; purposive corpus; two languages; Layer C covers only exercised code; **no human audit, so accuracy on natural code is not measured** (§V) |

**Demonstrated vs. claimed.** The quantitative findings Q1–Q3 are demonstrated within the benchmark.
The recommendations (§IV) are reasonable generalisations, but they go beyond the evidence in one
respect. The paper shows how *payload* ratios behave. It does not show how *agent* cost behaves, and
§IV correctly says so.

### 2.3 Cross-cutting validity

- **Construct.** Payload tokens are a proxy. The paper says so (§IV, §V), but the title and abstract
  are about "token-reduction ratios", which practitioners read as cost. Weinberger & Hozez (2026)
  show that token reduction correlates only weakly with billed cost (r = 0.15).
- **Conflict of interest.** G1 is the authors' prototype. The adapters for *competitors* were also
  written by the authors (cbm ambiguity follow-up, name resolution). Pre-freeze changes to name
  resolution are disclosed. The attached PDF does **not** state that G1 is the authors' own; the
  newer build fixes this.
- **Anonymity.** The figure "85.8×" appears in the public README of the G1 repository, so a
  reviewer can de-anonymise the paper with one search. **[V]** That README is in this repository.
- **Reproducibility.** Strong. `FREEZE.md`, `REPRODUCE.md`, pinned commits, the scored rows, raw
  outputs and pre-fix results are all released. Raw output *text* is not stored (counts only), so a
  token re-count needs a re-run.
